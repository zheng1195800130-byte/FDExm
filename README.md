# FDE Desk

个人 Windows FDE 桌面工作台。继续在 Codex 中开发，由 FDE Desk 管理资料、需求确认、工作记录和日报。

## 启动

```powershell
npm ci
npm start
```

也可双击 `启动 FDE Desk.vbs`。开发源码使用 `npm run dev`；已有打包程序时，普通启动优先打开它。构建程序在 `release/FDE Desk-win32-x64`，需要保留完整程序目录。

## 本地数据与源码分离

项目选择框下的“管理项目”可归档已完成或暂不关注的项目。归档后工作台与悬浮框的列表同步移除该项目，不参与全部项目整理与日报汇总。历史资料、需求、备忘录、日报及会话关联保留；在“已归档”中点击“恢复关注”即可继续使用。

从 0.5.7 开始，源码版和打包版默认共用 `%LOCALAPPDATA%\FDE Desk\data`。工作台左侧“本地数据”可打开目录或复制路径。

```text
%LOCALAPPDATA%/FDE Desk/
├─ data/
│  ├─ store.json                 项目、模型地址/名称及整理预设
│  ├─ store.backup.json          最近有效档案备份
│  ├─ model-key.encrypted        Windows 系统加密的 API Key
│  ├─ 整理规则.md                个人基础整理规则
│  ├─ projects/<项目编号>/       资料副本、备忘录、需求、每日收录和日报
│  └─ runtime/                   加密配套信息、界面缓存、本机草稿与实例锁
├─ backups/                     首次迁移的原始管理数据备份
└─ migration-*.json              迁移校验记录
```

客户原始资料、开发仓库仍留在你关联的位置，只建立索引；手动补充资料和截图才保存副本。首次升级会备份并校验旧 `data`，迁移管理文件、更新内部资料路径，旧数据不删除。多个旧档案均有内容时不擅自合并，损坏档案不替换为空项目。已有统一档案优先，不被旧软件目录覆盖。临时浏览器缓存不迁移；从 0.5.8 起保留 `runtime/browser/Local State` 等系统解密配套信息，不能将整个 runtime 当成可随意删除的缓存。

`FDE_DATA_DIR` 可显式指定独立数据目录，主要用于测试或自选存储；它不会触发旧数据迁移。请将自选目录放在源码仓库之外。API Key 使用 Electron safeStorage / Windows DPAPI 加密，备份时需要同时保留 `model-key.encrypted` 和 `runtime/browser/Local State`，不能只复制密钥文件；通常不能直接复制到另一台电脑使用，换电脑需重新填写密钥。

Git 仅同步源码、匿名示例和文档；不上传客户资料、聊天记录、模型密钥或软件运行数据。`.gitignore` 排除管理目录、备份、构建产物、截图验收输出和 `.env`。提交前运行 `npm run check:publish` 检查 Git 暂存区，能拒绝误加入的数据文件及常见密钥格式；该检查不能识别所有业务敏感内容，新增文档仍需自行核对。不要强制提交被忽略文件，也不要上传带旧 `data` 的软件压缩包。

可运行 `git config core.hooksPath .githooks` 启用每次提交前的自动检查。本仓库不附带客户档案、真实模型密钥或个人 Codex 会话。

## 日常使用

1. 关联原始资料目录与 Codex 开发目录；默认只收录客户资料，开发成果可单独开启。
2. 首次建立项目后确认正在使用的 Codex 会话入口；关联保存后持续复用，除非主动更换会话。平时不监听或读取会话。
3. 资料库与悬浮框按目录浏览，支持关键词、格式和标签筛选，复制文件/路径、打开所在目录。文件变更后点击“刷新”。已删除源文件从列表隐藏，保留内部身份方便恢复。
4. 点击整理时从当日对话中识别文件/目录用途，本地生成有依据的标签；目录标签供子文件检索，人工标签优先。标签识别不单独调用模型。
5. 只保留菜单“整理今天全部项目”和项目概览“整理当前项目”两个整理入口。点击后先刷新资料、读取绑定会话的上海当日对话，再联合整理项目介绍/进度、需求与待客户确认的问题、工作记录和日报；相关多轮修改合并记录。全部整理逐项目处理，某项目失败不影响其余项目。
6. 原始收录默认折叠，日报默认 Markdown 预览，可以编辑、保存、复制、导出。人工内容和已保存日报受到保护。

关联、切换项目、查看页面、刷新资料与重启均不读取新对话；没有后台会话监听或定时同步。仅点击两个整理按钮时读取当日内容，不补抓昨日或全量历史。重复点击无新增时不请求模型，失败不自动重试。零点只保存已有本地结果、开始新一天，保留已记录的遗留事项；没有点击整理的对话不会被后台补收。读取范围有限，不保证覆盖所有文件正文。

完整项目摘要、待办卡点与整理状态集中在“项目概览”。需求、工作记录和日报展示同一次整理保存的对应结果，不重复显示整理状态栏，不另设整理按钮。原始对话仅在“Codex 收录”折叠查看上次已保存的内容，不重新抓取。状态区区分本次整理是否成功和上次成功整理时间；失败仍显示原保存内容，人工修改和已保存日报保留。

模型返回重复编号、自身关联或已有别名时，程序按明确身份先归并，再统一保存；标题相同、来源相同不会自动认定是同一需求。无效来源继续拒绝保存，不自动追加模型请求。

## 悬浮框与备忘录

关闭工作台或“收起为悬浮球”进入悬浮模式，点击球展开资料/备忘录。快捷键 `Ctrl+Shift+Space`，系统托盘也可打开窗口或退出。

悬浮框默认约 430×620，可拖动边缘或右下角放大；文件列表和备忘录随窗口扩展。本次收起再展开保留尺寸，重启恢复默认。可为每个项目粘贴文字、截图和图片，自动保存；备忘录不会自动发送给模型。

备忘录的“扩大”按钮打开接近工作台大小的独立窗口，只显示当前项目备忘录，可拖动调整大小；返回悬浮框或关闭窗口时先保存最新输入，保存失败会保留窗口和草稿。两种窗口均支持“编辑 / 预览”，按 Markdown 展示标题、列表、表格、引用和代码块，切换显示不改变原文。粘贴的截图和图片保存在同一份项目备忘录中；Markdown 外部图片仅显示文字引用，不自动联网加载。

若两个窗口同时编辑同一项目并产生冲突，保留当前草稿并停止自动覆盖，提示核对后点击“重试保存”。

## 模型与整理风格

在“Codex 收录 → 模型设置”填写服务地址和密钥，可获取模型列表、筛选、测试并保存。支持 OpenAI 兼容接口、Anthropic 原生接口、DeepSeek 及本地 Ollama 等预设。获取列表不发送项目正文；测试连接可能产生模型调用。

左侧“模型整理预设”可粘贴日报样例、填写简洁程度和表达要求，所有项目共用。留空沿用当前基础规则；可以查看规则或恢复基础风格。保存预设只保存本地设置，不调用模型、不重算历史，下次整理新增内容时随同一个请求发送。样例只参考风格，不当作项目事实。

点击整理时，所选资料摘录及对话内容会发送到你配置的模型服务；Git 忽略与模型请求是不同的数据流。背景不发送。确认问题保留场景、临时处理、待问客户的问题及来源；临时功能完成不等于原业务缺口解决。

## 资料展示设置

左侧“资料展示设置”共用 `.gitignore` 风格规则，可直接编辑或导入文本。默认隐藏常见代码、日志；只影响列表/搜索/数量，不删除文件或改变模型整理范围。

搜索覆盖已索引文件名、用途、标签、相对目录及成功提取的正文，空格分开的词须全部匹配，提供命中片段。无 OCR、压缩包内部检索和语义检索；单文件正文最多提取前 80,000 字符，大文件及旧 Office 有解析限制。

## 开发与验证

```powershell
npm test
npm run pack -- --stage-only
```

打包输出在源码外的 `.fde-build/output`；不包含个人数据。默认打包也可复制程序到 `release`，更新正在运行的软件前先退出 FDE Desk。桌面验收脚本使用 `FDE_DATA_DIR` 与独立 Codex 目录隔离测试；迁移/启动验收另使用独立 `LOCALAPPDATA`，不访问真实数据。

只读个人项目审计需显式配置 `FDE_AUDIT_PROJECT_ID` / `FDE_AUDIT_THREAD_ID`，历史审计另需 `FDE_AUDIT_DEV_DIR`，仓库不内置个人路径或会话编号。

开源依赖与许可见 [开源复用说明](docs/开源复用说明.md)，各版本验收见 [验证结果](docs/验证结果.md)。

日报以所选日期的对话工作成果为依据。资料库内容只作为业务背景和需求证据，不因文件存在或更新就计为当天已完成工作。仅补充资料时保留当天已有成果；模型日报遗漏工作编号时，本地按已核实工作补齐，不额外请求模型。旧版自动日报在展示时按当天工作记录恢复，原记录不改写。单项目和全部项目汇总共用取数规则，汇总包含当前未保存的手工草稿；自动生成的缓存随新成果更新，已保存人工日报保留。

## 0.5.13 当日证据与客户确认覆盖

日报按项目写一两段简短进展，保留业务功能与待测试、待客户回复事项；中间步骤、测试次数和逐单数据留在工作记录。当前进度采用当天最后有效结论。

人工点击整理时，每次正文预算仍为 18,000 字符。长对话与资料分段提交，成功处理的片段不重复发送，未读完的证据保留待整理；最新对话优先，浏览器环境说明在本地移除。旧版已缩略的所选日期在首次手动整理时补读一次，后台不触发模型。

编号客户确认单优先读取，按主题分别保留场景、现行处理与具体问题；漏掉编号问题或把不同编号过度合并时不提交结果。Word 正文、表格及连续文字片段按原顺序提取，避免评分表被归入其他主题。确认日期只采用真实对话引用，不使用文件修改日期。包含较多客户问题的请求允许较长输出，仍只发起单次请求，无自动续算或重试。
