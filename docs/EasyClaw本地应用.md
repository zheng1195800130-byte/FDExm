# EasyClaw 本地应用

FDE Desk 的业务源码仍在本项目。EasyClaw 本地应用通过正式宿主入口创建，使用原有页面和独立原生程序。更新由本项目构建后同步，不需要修改 EasyClaw 宿主。

个人资料、需求、工作记录、日报、备忘录和加密模型密钥继续存放在 `%LOCALAPPDATA%\FDE Desk\data`。同步程序不复制这些文件，账号授权也在该数据目录内。授权安装脚本只保存当前账号的哈希，不保存账号令牌。

页面通过 EasyClaw 官方账号桥请求本机服务。服务向官方 UserInfo 接口验证身份，只有与已授权账号一致时才返回数据。未登录、其他账号和认证服务失败时拒绝访问。请求不相信页面提供的账号编号。普通浏览器停在访问提示。随应用交付的原生程序默认启用账号保护模式，直接双击也不能绕过验证。

“打开悬浮框”显示独立窗口，可收起为悬浮球，并继续使用同一档案。EasyClaw 页面仍保留；宿主关闭、授权过期或切换账号后，原生窗口隐藏并清空内容。悬浮窗口需要宿主持续提供授权，长时间隐藏页面也可能需要重新验证。

宿主请求最多等待 30 秒，单次响应最多 2 MiB。适配器将操作放入受保护任务，再分段取回结果，支持已有大档案与较长的整理操作。每次读取重新检查账号，授权撤销后废弃尚未读取的结果。

此隔离控制 EasyClaw 应用请求。Windows 本地文件的访问仍取决于 Windows 账号权限。

日报、工作记录和需求清单按上海日期保存，每次整理形成可回看的版本。默认追加更新；“重新整理当天”重新读取已完成对话并生成新版本。主档案和独立版本文件回读通过后才提示保存成功。次日更新需求不会改变昨日清单。历史版本与个人档案一起保存在应用目录外。

构建和更新：

```powershell
npm run pack -- --stage-only
node scripts/sync-easyclaw.cjs --app-root <宿主正式创建的应用目录>
```

首次授权已有档案：

```powershell
node scripts/provision-easyclaw-owner.cjs
```

授权脚本要求已有档案、已登录的当前宿主账号；如果已有授权属于另一个账号，会停止，不自动改绑或替换数据。

企业版使用不同账号、同时保留原授权时，为该安装建立独立档案：

```powershell
node scripts/sync-easyclaw.cjs --app-root <应用目录> --isolated-account --port <独立服务端口>
node scripts/provision-easyclaw-owner.cjs --app-root <应用目录> --state-root <当前宿主状态目录>
```

该安装的数据和授权保存在 `%LOCALAPPDATA%\FDE Desk\accounts\<应用标识>\data`。首次进入为空，不读取或复制原安装的资料、模型密钥或设置；后续更新沿用该独立档案。授权脚本不会改绑已有授权，也不会自动认领缺少授权的已有档案。运行时仍由正式 UserInfo 验证账号，不将身份文件作为登录凭据。

企业版的受管页面通过内联脚本提供正式登录桥。宿主入口在该脚本执行后恢复与原桌面页面一致的严格内容安全策略；不增加 `unsafe-inline`，独立桌面入口保留原静态策略。

同步时为内容过滤模块生成字节相同的 `.js` 地址，适配受管预览的脚本类型。空档案首次进入显示关联项目入口，不要求已有项目。
