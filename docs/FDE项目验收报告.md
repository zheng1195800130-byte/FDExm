# FDE 项目实际使用检查

检查日期：2026-10-09。检查对象为你已建立的 FDE 项目和当前 Codex 主聊天。

## 0.2.0 当前检查

本轮已实现从持续使用的 Codex 会话中按日期整理短工作草稿，并生成待核对日报。无需要求每轮答复都附上固定四行字段；有明确字段时仍可直接收录。普通自然语言可通过可配置在线模型整理，未配置真实密钥时使用本地整理，二者能力与验证证据分别记录。

### 已取得的证据

- 56 项核心测试以提升权限运行，全部通过，无失败、无跳过。
- `summary-smoke` 桌面专项通过：实际设置表单及服务类型选择、服务地址变化后的密钥隔离、测试后清空密码输入框、Windows DPAPI 密钥保护、后台同日合并和跨日保存、失败保留历史以及重启恢复。换服务地址后，暂存的旧密钥不会复用。
- 源码 IPC 页面来源与目录操作回归通过。
- 模型服务使用本地 HTTP mock，尚未调用真实 DeepSeek。本轮不能据此宣称真实自然语言摘要质量已验收。
- 源码真实项目副本检查读取当前主聊天 12 轮，含 2 个媒体引用；得到 1 项本地明确字段记录，按日摘要覆盖 2 天。检查前后真实项目数据文件哈希一致，没有把测试记录灌入真实项目。
- 通用桌面流程遇到剪贴板访问失败，独立复现 Windows `OpenClipboard: Accessdenied (5)`。显式设置 `FDE_TEST_SKIP_CLIPBOARD=1` 后，其他项目、资料、文字收录、按日工作与日报、悬浮、重启流程通过；剪贴板相关检查本轮不计通过，主程序原有剪贴板逻辑未改。

### 使用方式与剩余边界

自动整理保存事项摘要和来源引用，不保存整天聊天正文。多轮处理在同一天合并，同一事项跨天分别留下工作快照。自动草稿带待核对状态，人工编辑、确认及已保存日报不会被后续整理覆盖；删除的自动稿也不会自动复活。

关闭自动整理、清除密钥、读取截断或模型请求失败时，已有摘要继续保留，不以空结果覆盖历史。切换 Codex 会话会隔离旧会话的自动结果，保留人工记录及旧摘要归档。

真实 API 密钥尚未提供。用户需在软件设置中填写密钥并启用模型，再用自己的业务对话核对自然语言归纳效果。自动整理结果仍不代表功能已测试通过或客户已验收；需求范围与项目阶段继续由使用者确认。

最终 0.2.0 便携版的自动整理专项、真实项目隔离副本检查和 IPC 回归同样通过。已备份现有管理区并完成正式更新，覆盖程序时校验原始管理数据不变，程序 SHA256 与待验收版本一致；新版已重新启动。关联仍为 `D:\FDE` 的当前主聊天，开发成果范围仍为 `D:\FDE\fde-desk`。

### 0.1.2 当时的能力与缺口

资料索引、检索、复制、打开目录，以及确认后的工作合并和日报生成属于本版可验证的功能。相同事项编号用于连接多轮处理，当日合并、跨天保留；图片保留引用，内容过长时保留原文件或对话来源。

**普通自然语言和多轮对话，还不能自动归纳成简短工作记录。** 当前提取器仅能识别有明确字段的答复，读取到聊天不意味着已经形成需求或工作记录。需求、工作与项目阶段仍需核对收录、人工维护，不能宣称已经全自动完成。

测试使用真实项目的隔离副本，里面的核对记录和日报只用于验收，不灌入你的真实项目。

### 0.1.2 验收结果

35 项核心测试全部通过。源码和便携版的真实项目副本验收均通过：清理后为 10 份有效成果，噪声 0；当前主聊天 11 轮可读。悬浮框在两种宽度下显示完整；“打开目录”正确传入文件路径。资源管理器接口返回值使用 mock，未自动操作系统窗口。

核对后的简短工作摘要可以生成日报，同日合并、跨日保留、附件引用和重启保存正常。真实项目中的需求、工作、日报未被测试填充，当前自然语言自动候选仍为 0。

现阶段可让 Codex 在有明确成果的最终答复中附上四行简短内容：`问题：`、`原因：`、`处理：`、`结果：`，工具即可提取为待核对候选；没有明确结果时保留“待验证”，不替你认定客户验收。这是现有结构化收录的使用约定，不能替代尚未完成的普通自然语言自动摘要。
