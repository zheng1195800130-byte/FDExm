2026-10-08 核对仓库与官方文档。直接使用的依赖版本见 package-lock.json；许可证随各 npm 包保留在便携包中。

文件复制使用 Windows .NET System.Windows.Forms.Clipboard.SetFileDropList，生成系统通用的文件剪贴板数据。会话监看复用 Node 内置 [fs.watch](https://nodejs.org/api/fs.html#fswatchfilename-options-listener) 系统事件通知，监听父目录以支持会话文件替换；不使用 fs.watchFile 轮询。没有另写桌面窗口系统、文件复制协议或 ZIP/XML/PDF 底层解析器。

打包仍使用 Electron Packager。当前宿主的 Node 环境中 extract-zip 解压会提前退出，因此打包脚本为其解压步骤接入 AdmZip，并先比对 Electron 官方 SHA256；不修改 node_modules 源码。应用运行时不依赖此兼容步骤。

## 评估过的完整项目

- [CodexMonitor](https://github.com/Dimillian/CodexMonitor)，MIT：完整 Tauri Codex 客户端，功能包括启动会话、执行任务和 Git 操作。用户保留现有 Codex 桌面端，本应用聚焦资料与工作管理，整体改造会引入不需要的客户端和编译依赖，因此未整体集成。
- [Codex Trace](https://github.com/PixelPaw-Labs/codex-trace)，MIT：专注会话浏览、工具执行跟踪和 live tail。实际阅读 parser/turn.rs、entry.rs 核对 final_answer、task_complete 与格式兼容处理；本应用独立实现较小的只读适配，未复制源码、未引入 Rust/Tauri。
- [Electron API Demos](https://github.com/electron/electron-api-demos)：官方 API 用法参考；未整体复制。

需求摘要、按日工作合并和项目周期规则属于本应用的业务部分，独立实现。Codex rollout 读取是非稳定内部格式兼容层，升级后需要适配；仅明确关联会话可进入收录页，不读取认证文件，不向 Codex 发送指令。

## 0.2.5 事件驱动与增量整理

复用 Node fs.watch 原生目录通知；同目录共享监听，匹配已关联会话文件、短暂去抖并检查已完成轮次。它是本地文件事件接入 FDE 内部整理服务，并非 Codex 官方 webhook。所有已绑定项目均监听；事件订阅失败明确提示，用户重新关联或手动整理时恢复，不退回定时模型请求。

轮次内容 SHA256 检查点、跨重启失败锁和增量合并属于应用业务逻辑。模型只收到新增/修订完成轮次与简短旧事项；旧来源和媒体由程序从可信档案补回，不让模型编造。规则保存不触发历史重算，用户可明确选择重整当前项目。没有引入新的 SDK 或轮询依赖。

## 0.2.0 自动整理

模型接入复用 DeepSeek 官方的 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 与 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 协议，使用 Node 内置 fetch，无新增 SDK 依赖。默认模型依照 [当前模型说明](https://api-docs.deepseek.com/quick_start/pricing/) 采用 deepseek-flash；支持兼容 JSON 输出的其他模型接口。

密钥保护直接使用 Electron safeStorage，在 Windows 由系统 DPAPI 加密；未另写加密算法。会话增量指纹、按日合并、来源引用校验与人工记录保护由本应用实现。自动化模型测试使用本地 HTTP 模拟服务，不依赖付费密钥。

## 0.2.1 通用模型接入与模型列表

继续使用 Node 内置 fetch 实现有边界的协议适配，不新增 SDK 依赖。OpenAI 兼容服务共用 Chat Completions 与 GET models 协议；Anthropic 使用原生 messages、models 接口以及对应认证头。列表只保存候选名称于设置弹窗，不把完整厂商响应写入项目档案。

预设地址依据各厂商官方文档核对：

- [Moonshot/Kimi 模型列表](https://platform.kimi.com/docs/api/list-models)
- [智谱 OpenAI 兼容接口](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)
- [硅基流动模型列表](https://api-docs.siliconflow.cn/docs/api/models-get)
- [OpenRouter 模型列表](https://openrouter.ai/docs/api/api-reference/models/get-models)
- [Gemini 兼容接口](https://ai.google.dev/gemini-api/docs/openai#list-models)
- [Anthropic 原生模型列表](https://platform.claude.com/docs/en/api/models/list)
- [Ollama 兼容接口](https://docs.ollama.com/api/openai-compatibility)

不同厂商的模型能力、区域地址与列表接口可能不同；通用协议支持不等于全部模型已实际验收。无标准列表的服务可手填模型名称，部分服务列表过大时显示受控数量并提示。所有认证与生成请求在主进程完成，不将 API Key 返回到界面。

## 0.2.3 关联事项与 Markdown

Markdown 展示复用 Marked 18.1.0 和 DOMPurify 3.4.16，依赖固定版本。按照 [Marked 官方安全说明](https://marked.js.org/using_advanced) 在解析后进行净化；应用进一步限制标签、属性与外链协议，原始 HTML 作为文本展示，不加载正文图片。未引入完整编辑器，保留原文编辑与预览切换。

关联事项使用已有模型整理请求中的同日与历史简短事项上下文，由模型判断业务关联；程序校验已有事项标识、合并真实来源与附件，并保护人工编辑、删除记录和已保存日报。没有为每次合并另加一次模型请求。

## 2026-10-10：Codex 成果同步与模型节流调研

本轮仅调研接入方案，未安装全局钩子、插件或切换既有自动整理方式。0.4.3 只修补已删除资料的界面展示，需求采集 VERSION4 与已有历史检查点不变。

现状核对：会话事件分别触发工作摘要和业务需求分析；已处理内容有增量检查点，但每次仍携带相关历史事项。需求单次正文上限 16 万字符，分块约 2.6 万字符，分块中也会携带旧需求和确认上下文。历史升级校正、模型配置变化或主动重整可能重新发送资料。客户甲原始资料缓存可提取正文约 200 万字符，智能配载约 14 万字符，实际发送受限量与增量规则约束，不能将缓存体积当成实际 Token 用量。日报由本地 Store 复用工作记录生成，不额外请求模型。当前未保留厂商返回的 usage，不能准确追溯每次计费 Token 或账单金额。

可参考项目（均为调研判断，未在本机安装验收）：

| 项目 | 可借鉴能力 | 对 FDE 的适用判断 |
| --- | --- | --- |
| [Team-Volt/agent-lcm](https://github.com/Team-Volt/agent-lcm) | 本地事件 inbox、去重、SQLite 检索、MCP、历史导入；无外部 API/向量服务依赖 | 优先借鉴本地采集、检索与限量上下文；它本身不负责客户需求清单、工作记录和日报 |
| [Team-Volt/codex-lcm](https://github.com/Team-Volt/codex-lcm) | Codex 生命周期事件、确定性提取摘要、压缩检查点 | 作者已标注将由 agent-lcm 替代，新增集成优先看后者 |
| [genspark-ai/codex-conversation-archiver](https://github.com/genspark-ai/codex-conversation-archiver) | 简短钩子通知、会话路由、静默失败 | 名称虽带 archiver，实际主要向 GenTerminal 上报状态和标题，不是完整对话总结器；适合借鉴通知机制 |

[OpenAI 官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks) 已说明 Stop、UserPromptSubmit、PreCompact、PostCompact 及本地 Windows 命令钩子。本机只读核对 codex-cli 0.162.0-alpha.2，features 列表 hooks 为 stable/true；尚未做真实回调安装验收。官方 PostCompact 事件列出的字段不保证直接提供现成业务总结，不能把“压缩发生”当成“成果总结已经完成”。当前 command/mcp_tool handler 可执行，prompt/agent handler 会被跳过；如另启 Codex 或用 Stop 延续再总结，仍有额外模型消耗，不能称为免费整理。

建议落地路线：全局 FDE 同步 Skill + 本地成果接收器，必要时配轻量 Stop 钩子。你说“同步 FDE”时，Codex 在当前已有上下文中输出本次增量；自动同步只在需求变化、有效成果、客户决定或暂缓事项等明确节点生成短包，不要求每轮问答总结。Stop 只投递已经生成的短包，不强制额外模型轮次；压缩事件仅作为补充检查点。

短包建议总长约 500—1000 汉字，只保留项目/会话与真实来源时间、事项稳定编号、问题原因/处理/结果、需求变更、场景/临时办法/待问问题及文件路径。FDE 按项目和上海日期校验、去重、更新同一事项，离线先排队；工作记录和日报默认本地生成，FDE 模型仅在主动合并或润色时调用。这样成果归档步骤可为零外部 API 请求，但 Codex 写短包仍占用自身额度。

不更换接入方式的备选：新增轮次先本地累计，在有效里程碑、主动整理或日报入口一次性整理；同一增量由一次模型输出工作/需求/待确认，不在两条流程重复发送；大表默认只送字段结构与必要样例；既有历史默认冻结，按选定日期补读；普通程序升级与模型配置保存不自动重整成功历史。配套增加按项目/用途的请求数、厂商实际 usage 与失败重试统计、单次和每日预算；usage 缺失时只显示字符量，不伪装精确 Token 或费用。

## 0.5.4 文件检索与展示调研（2026-10-10）

- [TagSpaces](https://github.com/tagspaces/tagspaces)：离线管理已有文件，以标签、目录和多条件检索定位；[搜索文档](https://docs.tagspaces.org/search/)说明多个词 AND、格式与日期等筛选。适合参考交互，本项目没有整体复制其 AGPL 源码或增加用户原件旁的 sidecar 文件。
- [Paperless-ngx 使用文档](https://github.com/paperless-ngx/paperless-ngx/blob/dev/docs/usage.md)：按标签、文档类型组织与保存常用筛选视图。[讨论 #5285](https://github.com/paperless-ngx/paperless-ngx/discussions/5285)明确提出大资料库只依赖搜索不易找、希望层级导航；[讨论 #6717](https://github.com/paperless-ngx/paperless-ngx/discussions/6717)反馈结果缺少高亮难以判断命中。它的归档流程与本工具保留原始目录的需求不同，不整套迁移。
- 实际复用 [node-ignore](https://github.com/kaelzhang/node-ignore) 7.0.12，MIT，作为生产依赖保留其许可，用于标准 .gitignore 匹配，包括通配符、否定、目录及大小写。避免自己造简化匹配器。

本轮落地：展示忽略设置与导入、文件类别筛选、多个关键词 AND、相对目录搜索、相关度排序及安全高亮片段；纯本地零模型。建议后续资料增多时增加“需求/样例/规则/会议”用途标签和常用资料收藏、保存筛选视图，这些是后续建议，未计入本版能力。暂不增加向量库或逐文件 AI 自动分类，避免额外模型消耗与维护。
